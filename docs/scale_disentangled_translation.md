# 尺度解耦翻译（Scale-Disentangled Translation）设计方案

> **状态**: 3 尺度全实验验证完成 + 质量瓶颈诊断完成 + 论文架构生成器已实施
> **当前**: 论文架构生成器 `ResnetGenerator_timestep_restime_3_mhsa` 3000 步训练中
> **目标**: 利用扩散模型 c_list 的多时间步层次化表示，实现结构-风格解耦的无配对图像翻译

---

## 1. 动机

### 1.1 问题根源

CycleDiff 在每个训练步随机采样单个扩散时间步 `t`，强制生成器在一个统一的参数空间中同时回答两个矛盾的问题：

```
精细层（t≈0.05）:  建筑边缘保留多少？道路宽度多少个像素？
粗粒度层（t≈0.9）:  整体配色变多少？区域纹理密度变多少？
```

生成器的策略：**降低所有层的梯度**——用最小的全局操作（降低 C 分量方差）同时"满足"两个约束。结果：精细结构被牺牲（`analysis_report.md` §3.2）。

**诊断实验确认**（`verify_scale_hypothesis.py`）：统一 SSIM w=15 训练后，生成器输出 `grad_fake ≈ 0.075` 在所有 t 上恒定（std=0.004）。精细输入（t=0.05, grad=1.18）被压缩 15×，粗粒输入（t=0.90, grad=0.09）几乎不变。FiLM 的 512 维条件管道形同虚设——生成器完全忽略了时间步信息。

**尺度解耦 2-scale MVP 效果**：训练后 grad_fake 标准差从 0.004 提升到 0.110（+2650%），A2B 梯度幅值从基线 13.91 提升到 16.38（+17.8%），远超统一 SSIM w=15 的 15.05（+8.2%）。

**3 尺度 5000 步终极效果**（含 P0+P1）：A2B 梯度从 13.91→**18.28**（+31.4%），Pixel PSNR 从 17.09→**19.19 dB**，C-space SSIM 从 0.525→**0.722**，A2B:B2A 差距从 30.2%→**8.3%**。详见 §6 实验验证。

### 1.2 核心思想

将扩散模型的 `c_list`（200 个时间步的层次化 C 分量）作为多尺度分解，在不同尺度施加不同的翻译策略：

```
c_list[0]    （精细层，t≈0.05） → 保守：保留空间结构（SSIM 约束）
c_list[100]  （中等层，t≈0.5）  → 折中：部分转换 + 部分保留
c_list[199]  （粗粒度，t≈0.95） → 激进：域风格转换（对抗损失约束）
```

这利用了扩散模型自带的层次化分解——不是引入外部新机制，而是让翻译器学会"在精细层保留、在粗粒度层转换"。

### 1.3 与 EarthMapper 的差异化

| 维度 | EarthMapper（自回归） | 本文（尺度解耦扩散） |
|------|---------------------|--------------------|
| 多尺度机制 | AR 生成过程的粗→细渐进生成 | **扩散 C 分量的结构-风格分解** |
| 尺度用途 | 生成分辨率递进 | **同一张图的不同抽象层次** |
| 结构保证 | 关键点 force（经验规则） | **尺度解耦（架构原生），精细层强制保留** |
| 域转换 | 全局统一 | **分尺度独立控制** |

## 2. 理论基础

### 2.1 C 分量的层次化性质

`reverse_q_sample_c_list_concat`（`ddm/ddm_const_ode_2.py:525-560`）提取 200 个时间步的 C 分量：

```
c_list[0]   t ≈ step         → 最清晰，边缘锐利
c_list[1]   t ≈ 2·step       → 较清晰
...
c_list[K-1] t ≈ sigma_max    → 最模糊，仅剩低频色块
```

**精细 t 的 C 分量编码了空间定位信息（边缘在哪里），粗粒度 t 的 C 分量编码了全局风格信息（色块配色）。当前训练在所有 t 上用相同的翻译规则——这是结构退化的根源。**

### 2.2 尺度解耦的数学直觉

令 $C_t$ 为时间步 $t$ 的 C 分量，$G_\phi$ 为翻译生成器。当前方案：

$$
\forall t: \quad \|C_t^{\text{fake}} - C_t^{\text{target}}\| \to \min \quad \text{（一刀切）}
$$

尺度解耦方案：

$$
\begin{aligned}
t \in [\text{eps}, 0.3]&: \quad \|C_t^{\text{fake}} - C_t^{\text{src}}\|_{\text{SSIM}} \to \min \quad \text{（保留结构）} \\
t \in [0.3, 0.6]&: \quad \lambda_1\|C_t^{\text{fake}} - C_t^{\text{src}}\|_{\text{SSIM}} + \lambda_2 D(G(C_t)) \quad \text{（折中）} \\
t \in [0.6, 1.0]&: \quad \max D(G(C_t)) \quad \text{（域转换）}
\end{aligned}
$$

生成器学会了："精细层我不管，粗粒度层我做翻译"——结构保持和域转换不再竞争同一组参数梯度。

### 2.3 诊断验证实验（已执行，结论明确）

在统一 SSIM w=15 训练后的模型上运行 `evaluation/cyclediff/verify_scale_hypothesis.py`：

```
诊断结果 (grad_fake 在 pretrain 后):
  t=0.05: grad_src=1.18, grad_fake=0.079  (退化 15×)
  t=0.50: grad_src=0.69, grad_fake=0.076  (退化 9×)
  t=0.90: grad_src=0.09, grad_fake=0.069  (几乎不变)
  
  grad_fake std across t = 0.004  ← 生成器在所有 t 上输出恒定梯度
```

**结论**: grad_fake 在所有 t 上 ≤0.08，std=0.004。无论输入 C 的精细程度如何，生成器输出相同的梯度水平。**一刀切行为确认。**

尺度解耦训练后的对比诊断见 §6.2。

## 3. 架构设计

### 3.1 Scale-ID 条件注入（已实施）

生成器（`ResnetGenerator_timestep_restime_2_attn`）已有时间条件 FiLM 管道。MVBP 添加了 2-scale 条件注入（`ddm/cycle_generator_2.py`）：

```python
# __init__ 新增 (line 398后)
self.scale_emb = nn.Embedding(2, 64)     # 2尺度: fine=0, coarse=1
self.scale_proj = nn.Linear(512 + 64, 512)  # 576→512

# forward (line 440)
def forward(self, input, time, scale_id=None):
    t = self.time_mlp(time)              # [B, 512]
    if scale_id is not None:
        s = self.scale_emb(scale_id)     # [B, 64]
        t = torch.cat([t, s], dim=-1)    # [B, 576]
        t = self.scale_proj(t)           # [B, 512]
    x = self.init_conv(input)
    # ... 下游不变
```

**关键设计**: `scale_id=None` → 向后兼容，仅在尺度解耦训练时传值。

**3 尺度升级**（已实施）：`Embedding(2,64)` → `Embedding(3,64)`，`scale_proj` 维度不变（64 维 embedding 始终拼接）。

### 3.2 多时间步训练循环（已实施，3-scale per-batch 择一）

每个 batch 随机择精细、中等或粗粒模式（各 33% 概率）。仅 net_G_A 接收 scale_id，net_G_B 不接收（B→A 方向无退化问题）。

```python
# 3尺度采样（已实施）
rand_val = torch.rand(1).item()
if rand_val < 0.33:
    t = eps + t_raw * 0.3;   scale_id_A = 0  # fine [eps, 0.3]
elif rand_val < 0.66:
    t = 0.3 + t_raw * 0.3;  scale_id_A = 1   # mid  [0.3, 0.6]
else:
    t = 0.6 + t_raw * 0.4;  scale_id_A = 2   # coarse [0.6, 1.0]
```

### 3.3 恒等映射修复（已实施）

恒等和 cycle 路径始终使用 scale_id=0（精细模式，不施加对抗）：
```python
scale_id_fine = torch.zeros_like(scale_id_A)
fake_C_T = self.net_G_A(input_C_S, t, scale_id=scale_id_A)     # 主路径: 跟 batch
idt_C_T  = self.net_G_A(input_C_T, t, scale_id=scale_id_fine)  # 恒等: 精细
recon_C_T = self.net_G_A(fake_C_S, t, scale_id=scale_id_fine)  # cycle: 精细
```

**效果**：恒等余弦从 0.870→0.898（+3.2%），方向正确但距基线 0.997 仍有距离。net_G_A 的共享编码器在粗粒 batch 中仍受到对抗梯度残余影响。

### 3.4 融合策略

训练时不同尺度分别约束。推理时将翻译结果注回 c_list，通过 `sample_from_c_list` 解码。c_list 本身是融合载体——不需要显式融合层。

## 10. 制图抽象与尺度解耦的对应关系

尺度解耦不只是工程优化——它反映了制图学中"选择性抽象"的核心原理。

| 制图操作 | C 分量层次 | 尺度解耦策略 |
|---------|----------|-----------|
| 保留道路边缘、建筑轮廓 | 精细 t（小 t） | scale_id=0：强 SSIM，不施加对抗 |
| 移除植被纹理、简化地形渐变 | 中等 t | scale_id=1：折中约束 |
| 转换整体配色、合并区域色块 | 粗粒 t（大 t） | scale_id=2：对抗主导，弱 SSIM |

扩散模型的 C 分量层次化分解恰好与制图抽象的"保留关键结构、简化非关键细节"流程一致——这是本方法不同于 EarthMapper（关键点 force 手动设阈值）和传统 CycleGAN（全局约束）的根本原因。

## 11. 对标 EarthMapper：性能超越目标

### 11.1 为什么 EarthMapper 是核心对标对象

EarthMapper (Dong et al., 2026) 是首个专为 BSMT 设计的深度学习框架，在 CNSatMap（302K 配对卫星↔地图）上取得了当前最优结果。其论文贡献包括：GJSA 多尺度自回归、地理坐标编码、语义注入（SI）和关键点自适应引导（KPAG）。

然而，EarthMapper 有三个根本局限：
1. **依赖配对数据**：302K 卫星↔地图必须精密对齐——采集成本极高，覆盖 38 个城市后难以扩展
2. **推理串行**：自回归逐 token 生成，10K tokens 的推理代价不可忽视
3. **结构保证依赖经验规则**：关键点 force 的阈值 τ 是全局手动设定的，不可微分、不可学习

**本文的尺度解耦扩散翻译在三个维度上提供了替代性优势**——非配对数据、并行推理、可微分结构保持。直接对标 EarthMapper 不仅验证了方法有效性，更证明了**扩散模型在 BSMT 任务上可以达到甚至超过自回归方法的性能，同时不需要配对数据**。

### 11.2 当前状态 vs EarthMapper 报告指标

> **注意**：EarthMapper 报告的指标在 CNSatMap (256×256, 58K 测试对) 和 New York (600×600, 1K 测试对) 上。本文目前使用 maps 数据集（evaluation/cyclediff 管道）。需要在 CNSatMap 上重新评估才能进行严格对比。以下目标基于双方报告指标的相对趋势设定。

## 13. 像素空间质量瓶颈诊断（2026-05-14）

### 13.1 问题：C 空间指标优异但像素输出差

3 尺度解耦训练后，C 空间指标大幅改善（A2B 梯度 +31.4%，C SSIM +40%），但像素空间改善微弱：

| 指标 | 基线 | 3-scale 20k | 改善 |
|------|------|-------------|------|
| **翻译 PSNR（像素）** | ~22.93 dB | 23.15 dB | **+0.22 dB** |
| **FID（vs 目标 GT）** | — | 261.3 | — |
| C SSIM (cycle) | 0.525 | 0.733 | **+40%** |
| C PSNR (cycle) | 24.19 | 27.78 | **+3.6 dB** |

### 13.2 诊断方法

在 `evaluation/cyclediff/diagnose_quality_gap.py` 中实施了 3 步诊断，测量了质量损失链中每一层的确切位置：

1. **VAE 天花板**——VAE 重建真实地图的精度
2. **LDM 重构保真度**——LDM 以给定 C 值进行编码→去噪→解码的精度
3. **C 空间翻译质量**——生成器经过翻译的 C 与实际目标 C 的距离
4. **完整管道 PSNR**——端到端 RSI→Map 的通道

### 13.3 诊断结果

```
质量损失链（配对测试集，50 个样本）：

VAE 天花板（编码 map → 解码 map）：       34.60 dB
    │
    ├─ LDM 重构损失：                     -1.73 dB
    │       LDM 自身重建（编码→C 列表→去噪→解码）：33.75 dB
    │
    ├─ 生成器 C 翻译损失：                -10.60 dB  ← 主要瓶颈
    │       C 翻译 L1：0.433（C 幅值 ~0.165）
    │       C 翻译余弦：0.897
    │
    ▼
完整翻译管道（RSI→Map）：                 23.15 dB
```

**归因**：

| 瓶颈 | 损失 | 占比 |
|------|------|------|
| LDM 重构 | 1.73 dB | 15% |
| **生成器 C 翻译** | **10.60 dB** | **85%** |
| 总计 | 12.3 dB | 100% |

### 13.4 关键发现

1. **VAE 不是瓶颈**——VAE 能重建 34.60 dB 的地图，是 30.66 dB 的（评估脚本确认）。瓶颈在其上游。
2. **LDM 质量优秀**——100 个采样步的重构 PSNR 为 33.75 dB（10 步时为 29.41 dB）。LDM 仅在损失链中贡献了 1.73 dB。
3. **瓶颈是生成器 C 翻译质量**——损失链中 85% 的损失来自生成器的不准确 C 翻译（L1=0.433，余弦=0.897）。生成器拥有仅 2 个下采样层和 LinearAttention（而非 MHSA），在跨域 C 翻译中表现不足。
4. **我们的 LDM 与论文机制的对比**——论文中的 CycleDiff 工作仅靠 C 空间操作，无需像素损耗——但其 LDM 是从头训练 100k 步的（我们的是 50k 步预训练）。然而，我们的 LDM 测试显示其在 100 个采样步下的重构 PSNR 为 33.75 dB——已足够优秀。差距并不在 LDM——而在于生成器架构。

### 13.5 后果：为匹配论文水平，需要升级生成器架构

论文的生成器使用的是：
- 3 个下采样层（瓶颈 64→32→16→8 = 8×8），而我们是 2 个（瓶颈 16×16）
- 编码器-解码器前的时间注意力模块（MLP → ResNet(FiLM) → MHSA）
- Multi-Head Self-Attention (MHSA)，而非 LinearAttention

我们的实现使用的是：
- 2 个下采样（瓶颈 64→32→16 = 16×16）
- 无独立的时间注意力模块
- LinearAttention（MHSA 代码存在但被注释掉）

## 14. 论文架构生成器实施（2026-05-14）

### 14.1 架构

在项目中新增 `ddm/cycle_generator_2.py` 类 `ResnetGenerator_timestep_restime_3_mhsa`：

```
Input C [B, 3, 64, 64]
    │
    ├─ init_conv: 7×7 Conv(3→64), InstanceNorm, ReLU
    │
    ├─ 预下采样（为了 GPU）：2× ResNetBlock(FiLM) + stride-2 Conv
    │       → [B, 128, 32, 32]
    │
    ├─ 时间-注意力模块（与论文规格一致）：
    │   ├─ ResNetBlock(FiLM, 128→128, 时间维度=512)
    │   ├─ MHSA(128, heads=4, batch_first)  ← 32×32 处 1024 tokens
    │   └─ LayerNorm(128)
    │
    ├─ 2× 下采样模块（32×32→16×16→8×8）
    │   各模块：ResNetBlock(FiLM)×2 + stride-2 Conv
    │
    ├─ 瓶颈：12× ResnetBlock_time（时间条件化，512 通道，8×8）
    │
    ├─ 3× 上采样模块（8×8→16×16→32×32→64×64）
    │   各模块：ResNetBlock(FiLM)×2 + transposed Conv
    │
    └─ 最后：7×7 Conv(64→3)
```

### 14.2 变更

**新增 class** `ddm/cycle_generator_2.py:473`：
- `ResnetGenerator_timestep_restime_3_mhsa` — 205M 参数
- MHSA 作用于 32×32 特征图（为适配 GPU 显存，MHSA 作用于下采样后），与论文中 3 次总下采样相匹配
- 保留尺度解缠（`scale_emb(3,64)` + `scale_proj`）作为我们的创新
- 为 `scale_id` 保持相同的转发签名

**配置更新**：
- `configs/maps/translation_cgrad.yaml` → `net_G.class_name` 指向新 class
- 训练参数：`batch_size=12, train_num_steps=3000, lr=1e-5/1e-4`
